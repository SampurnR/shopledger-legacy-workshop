### What the app does

ShopLedger is a small shop billing and record-keeping app. Staff can select products, make an order, record payment as cash, UPI, or customer credit (“Khata”), and see order history, customer balances, stock, and GST reconciliation. It stores its records in a local JSON file rather than a database. The UI describes the shop and GST details in public/index.html, and the server serves that UI and the API in server.js.

Some domain terms used in the code:

- Khata is a customer credit account. An order charged to Khata increases the customer’s billed amount, subject to a credit limit; settlements record payments against the balance. See ledger.js.
- GST is the tax calculated on the order. The code splits it into CGST and SGST, described as an equal split for an intra-state Maharashtra sale in tax.js.
- HSN is the product classification code used here to select a GST rate. The configured prefixes map to 5%, 12%, or 18%; unmatched codes use an 18% default in config.js and tax.js.
- Physical stock is the product’s stock count. Reserved stock is deducted from physical stock to calculate sellable stock: max(0, stock - reserved). This is presented as stock held for wholesale quotes in inventory.js. When an order is placed, however, the code reduces physical stock directly.
- Order ledger means the order record’s stored subtotal, discount, tax, and total. The invoice code independently recalculates figures and the reports compare those calculations in reports.js.

### Order placement, step by step

1. The user selects products and quantities in the catalog. The browser code keeps quantities in cartQuantities; getSelectedCartItems() creates the cart data. The UI and order controls are in index.html, and the cart functions are in app.js and app.js.
2. updateCartPreview() sends the cart and coupon to POST /api/pricing/preview. The route resolves product IDs and computes preview totals with pricing.subtotal(), coupons.validate(), and pricing.computeTotals(). See app.js and routes/reports.js.
3. Clicking “Place Order” sends the selected items, customer, payment mode, status, and coupon to POST /api/orders. See app.js.
4. The order route reads the JSON store, rejects an empty cart or unknown product, and rebuilds each line from the product record. It takes the product’s stored ID, SKU, name, HSN, and price; it parses quantity as an integer. See routes/orders.js.
5. inventory.check() checks requested quantities against sellable stock. If the check passes, pricing.subtotal() and the coupon helpers validate the code and compute the discount. pricing.computeTotals() allocates the discount proportionally across lines, calculates GST on each line’s discounted taxable value using its HSN rate, and returns the tax and total. See routes/orders.js, pricing.js, and tax.js.
6. If payment mode is khata, the route requires a customer ID and calls ledger.chargeOrderToKhata() with the order total. That checks the customer’s projected balance against their credit limit and updates the billed amount. See routes/orders.js and ledger.js.
7. The route calls inventory.reserve() to subtract the ordered quantities from physical stock. It then calls orders.add() to assign an ID and date and append an order record containing the customer, payment mode, status, items, coupon, subtotal, discount, tax, and total. See routes/orders.js and orders.js.
8. The route appends an ORDER_CREATED audit entry and calls store.write() to serialize the updated object to data/db.json, then returns the order to the browser. The UI clears the cart and reloads products, dashboard totals, and customers. See routes/orders.js, store.js, and app.js.
9. The invoice link opens the server’s invoice route. It calls invoice.render(), which calls computeInvoiceFigures() and calculates the displayed GST and total from the saved line items and coupon. See server.js and invoice.js.

### Risks and maintenance concerns visible in the code

- Order cancellation appears not to restore stock. Orders store item IDs as id in orders.js. Cancellation calls inventory.release(), which looks up items[i].productId and reduces reserved; the stored order items do not show that property, and order placement reduced stock directly. See orders.js and inventory.js.
- The stock check rejects ordering the full remaining sellable quantity. It fails when qty >= sellable, rather than only when the requested quantity exceeds availability. A request for exactly the sellable amount is rejected in inventory.js.
- Invoice and order totals use different tax and coupon calculations. Order pricing resolves GST from HSN, applies the coupon against subtotal, and taxes the discounted line values in pricing.js. Invoice calculation uses gstRate if present, otherwise the default 18%, and calculates coupon percentage against subtotal + tax without applying the configured maximum discount. Saved order lines from the route contain HSN but no gstRate. See invoice.js and routes/orders.js. Reconciliation detects differences, but does not make the two calculations consistent.
- Date filtering and sorting are fragile. Dates are stored as DD/MM/YYYY; normalization changes HTML date input into the same format, but the code compares those strings lexicographically. That does not sort or filter dates chronologically across months and years. See dates.js and orders.js.
- Validation is limited. Quantities that are invalid or below one are silently changed to one in routes/orders.js. The settlement route passes the request amount directly to the ledger, where checks use JavaScript comparisons and arithmetic without first requiring a finite numeric value. See routes/customers.js and ledger.js.
- JSON persistence is synchronous and has no visible write coordination. Each request reads and writes the whole file synchronously; a write is a direct overwrite, with no atomic-write or concurrent-update mechanism shown. See store.js.
- Dependencies are declared with version ranges. package.json uses ^1.19.0 for body-parser and ^4.17.1 for Express, so the manifest does not pin exact versions. See package.json.
- The test script explicitly reports that no test is specified. I found no test files in the listed repo files. See package.json.
- Some admin/config documentation appears stale. config.js says the admin key is used by export and reset, but the visible route file only implements /admin/export. See config.js and routes/reports.js.
