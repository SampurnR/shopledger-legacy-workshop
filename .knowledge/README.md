# Ticket Knowledge Records

Create one concise Markdown record per ticket using `ticket-N-topic.md`.

Each record should preserve enough context for another contributor or agent to resume work without reopening the full investigation:

- ticket ask and acceptance criteria;
- relevant modules and data shapes;
- observed current behaviour and root cause;
- proposed plan, risks, and rejected alternatives;
- implementation that worked and attempts that did not;
- tests, runtime verification, review result, and remaining limitations;
- changelog notes when user-visible behaviour or data compatibility changes.

Do not copy credentials, customer records, local machine paths, environment values, or other sensitive data into these files.
